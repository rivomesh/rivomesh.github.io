## 全局验收场景与证据要求

| 场景 | 最低检查 |
|---|---|
| 两节点统一控制 | A操作B、B故障接管、旧owner恢复、断网后结果未知与重查、相同请求重复路由；全局权限撤销立即按策略生效 |
| 登录保持 | 刷新、新标签页、过期、退出、跨节点路由、控制器重开、权限变更、CSRF和身份冲突；登录恢复不发出额外任务动作 |
| 目标事务跳过 | 单事务跨多表、指定一个/多个目标、重复请求、回执提交后ACK丢失、旧代次/旧错误版本、已实际提交的事务、审计不可写 |
| 采集/解码故障 | 有/无完整边界、已知/未知影响、原日志不可读、日志被清理、错源、全部相关订阅；不支持执行时显示可恢复路径 |
| 补数据/补偿 | 同键多次修改、主键移动、插入后删除、无主键相同行不同身份、NULL/JSON/微秒时间/大数、结构/依赖变化、漂移、取消/强杀及重试 |
| 缺口台账 | 跳过后仍显示缺口，不把覆盖当应用；补齐后凭对账证据关闭；接受丢失与验证修复分别记录 |
| 部署与升级 | Linux/Docker/Helm/原生K8s、持久存储/本地磁盘、节点/控制器/卷故障、配置和密钥轮换、旧状态迁移或明确拒绝 |

### 发布证据模板

需求ID、任务ID、用例ID、候选包SHA、节点/Agent协议、真实产品/版本/模式、JVM及架构、驱动、存储/持久性、源/目标范围、工作负载、操作前后坐标、回执/缺口ID、正常/错误/重复/中断结果、原始日志位置、脱敏方式、文档入口、遗留边界。状态至少区分NOT_RUN、PASSED、FAILED、EXPERIMENTAL、UNSUPPORTED；单纯存在脚本不能标PASSED。
