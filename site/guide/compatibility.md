# 能力与兼容性说明

状态依据：源码 `AdapterCatalog.java`、最新实施状态及 RM-SDD-001。**产品名称出现在目录里，不等于该产品的所有版本、模式、集群与 JDK 均已通过验证。**

## 状态如何理解

| 状态 | 含义 |
| --- | --- |
| 可用 | 已实现并有指定档案的代表性链路验证，仍需核对版本范围 |
| 部分验证 | 首批传输/物化/恢复已有证据，完整集群、安全或容量等尚未完成 |
| 实验性 | 仅特定模式首批适配，完整兼容性与恢复矩阵尚未完成 |
| 规划中 | 没有可用实现，不应作为当前可选能力 |

[连接器目录](/ecosystem/)逐项列出源端、目标端和状态，并连接到运行手册。

## 源数据库与 Java

当前实际采集源为 MySQL。5.7.44 有基础链路记录，8.0 有历史 V2/HA 记录，8.4 有代表性 V3 全量、增量与恢复验证；各版本不等于全功能验收。MySQL 8.2 独立完整档案、PostgreSQL 源与 Oracle 源仍是 SDD 待办。**PostgreSQL 作为目标可用，不代表 PostgreSQL 作为源已实现。**

代码以 Java 8 为基线；Temurin 8/11/17/21/25 有历史包的指定 SQL 冒烟记录，不覆盖当前完整平台和所有驱动。完整运行时矩阵见 [JV-01～JV-04](/reference/sdd/001-control-recovery-compatibility/spec#java运行时兼容)及[性能手册](/reference/zh-CN/performance)。

## 同步与恢复边界

- 首次目标业务表要求为空，程序不自动清空已有数据；目标由同步服务独占写入。
- 运行中的未支持 DDL 会阻断同步；当前不提供任意表结构自动演进。
- 多个目标独立确认，不承诺跨目标分布式原子事务。
- 消息目标为确认后至少一次投递；消费者仍需按协议去重。
- Web 共同校验点修复首版限定 MySQL 8.4 / PostgreSQL 17 业务目标，计划需管理员审阅；不是失败事务手工跳过或业务切换。
- Worker 租约/隔离与代表性接管验证已存在；单控制器浏览器会话首版见[会话手册](/reference/zh-CN/browser-sessions)；统一跨节点控制、共享会话和控制面 HA 仍在 SDD 计划中。
- Linux / Docker / Helm / Kubernetes 文件已提供，静态清单检查不等于真实 K8s/CSI 故障验收。
