# 常见问题

## 没有数据同步经验，可以从哪里开始？

先阅读[项目介绍](introduction)理解源、目标和全量/增量，再按[快速开始](quick-start)启动控制台。数据库日志、权限和备份由熟悉数据库的同事协助配置；向导可以减少配置工作，但不能替代数据库环境准备。

## 是否需要修改原业务代码？

MySQL 增量从数据库变更日志读取，通常不需要在业务代码中加入同步逻辑。仍需要启用指定日志配置、授权账号，并评估全量快照对源库的影响。

## 这是正式稳定版吗？

当前为 0.1.0-SNAPSHOT 发布前版本，用于评估与试点。没有把尚未发布的安装包、公共镜像或稳定版本写成可下载产品。[获取页面](/download)说明当前构建方式。

## 能直接接管已有数据的目标库吗？

首次目标要求空表或空 schema。当前不自动清理或合并非空业务数据，非空接管与业务切换仍在 SDD 计划中。

## 一个目标故障，其他目标也会停止吗？

V3 目标独立投递和确认，单个目标 SQL 故障可独立暂停。日志回收受最慢目标约束，容量耗尽可能使源端进入背压等待，所以需要监测积压和磁盘。

## “恢复”是否会跳过失败记录？

默认恢复会重试原失败事务。人工跳过、失败事务前镜像补偿、用户补丁和缺口台账仍是 SDD 待办。当前共同校验点修复是一条独立的审阅式工作流。

## 浏览器会话如何恢复？

最新单控制器会话首版使用 HttpOnly Cookie，可在未过期时刷新恢复身份，不把长期令牌存入 Web Storage。控制服务重启会清空内存会话，需要重新登录；跨控制节点连续性仍未完成。配置与权限撤销规则见[浏览器会话手册](/reference/zh-CN/browser-sessions)。

## 网站会连接或上传我的业务数据吗？

本站是静态介绍与文档网站，站内搜索在浏览器本地运行。实际控制台运行在你部署的服务环境，本站不会要求填写数据库密码或访问令牌。

## 怎么报告问题？

按[贡献指南](/community/)准备版本、已脱敏配置、错误与复现步骤。不要提交数据库密码、访问令牌、完整业务原始值或未脱敏日志。
