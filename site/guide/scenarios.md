# 场景与试点建议

下列是可评估的使用方式，不代表客户案例或生产验收。选择前请核对实际产品版本、数据类型、权限和故障恢复要求。

## 国产数据库适配评估

**典型需求：** 原业务使用 MySQL，希望先把数据同步到国产数据库验证应用兼容性。

**建议路径：** 从一个业务库、少量代表性表开始，验证中文、金额精度、时间、JSON、无主键和索引语义。openGauss 有指定版本验证；达梦、金仓、GBase 8c、OceanBase 为实验档案，逐一查阅产品手册。

**交付判断：** 比较字段值与事务结果，测试目标停机、进程中断和错误恢复，记录不支持对象。当前同步和修复成功不等于已经完成业务写入切换。非空接管、约束重建、切换与回退见 SDD 的 LG-02。

## 业务数据进入分析系统

**典型需求：** 将 MySQL 变化持续送到 ClickHouse、Doris 或 Hive，为分析提供数据副本。

**建议路径：** 使用独立目标，按相应手册配置物化视图、回执与读取方式。先验证更新/删除可见性和重启恢复，再评估真实业务规模。

**交付判断：** 各分析目标按自身版本物化协议工作，不应视作普通关系库的跨表事务。Hive 还需要遵循查询结果缓存设置要求。集群、安全和容量矩阵仍需验证。

## 一份业务数据，服务多个下游

**典型需求：** 同一 MySQL 的订单、库存数据，需要进入关系库、分析库或消息系统。

**建议路径：** 在 V3 中显式配置库映射和多个目标，按目标分别观察确认与积压。先验证一个慢目标或错误目标的隔离及恢复行为。

**交付判断：** 目标独立确认，整体不存在统一的分布式原子提交。日志按最慢目标回收，应预留停机积压容量。消息投递至少一次，需要消费者按协议去重，Broker 确认不代表业务消费完成。

## 面向政企团队的试点清单

| 环节 | 业务人员准备 | 技术人员核对 |
| --- | --- | --- |
| 范围确认 | 业务库、表、用途、数据敏感级别 | 版本、类型、对象与适配状态 |
| 环境准备 | 独立测试环境与维护窗口 | 网络、账号、GTID、磁盘与备份 |
| 首次验证 | 典型业务操作样例 | 全量、增量、值比对、延迟观察 |
| 故障演练 | 可接受停机与恢复目标 | 进程/目标故障、重试、日志保留 |
| 评审记录 | 验收结论与待解决问题 | 实际版本、配置、证据和限制 |

项目不承诺统一的 TPS 或恢复秒数。建议按[性能手册](/reference/zh-CN/performance)记录硬件、网络和数据分布，形成自己的试点评估。
