# 场景与试点指南

数据库改造与数据集成可以从下面三类场景开始，按“业务定义范围、技术验证链路、双方审阅结果”的方式开展试点。

## 信创数据库适配与改造

把 MySQL 的代表性业务数据同步到独立目标环境，验证中文、精度、时间、JSON、无主键与索引语义。openGauss、达梦、金仓、GBase 8c 与 OceanBase 应分别按指定版本和模式阅读手册。

完整实施步骤见[信创数据库适配与改造](xinchuang)。先核对值和事务结果，再演练目标停机、进程中断和错误恢复。数据同步成功不代表约束重建、应用接管与回退已经完成；正式切换需要单独制定接管与回退方案。

## 业务数据进入分析系统

将 MySQL 已有数据与持续变化写入 ClickHouse、Doris 或 Hive。按目标物化协议和读取方式检查更新、删除与重放结果，再测量业务负载下的延迟和容量。

这些目标不使用完全相同的事务语义。Hive 的结果缓存、ACID 视图等前提请阅读专门手册。

## 同一来源服务多个下游

一条同步任务可配置多个 database 与多个目标，分别观察每个订阅的进度。验证一个目标故障或变慢时其他目标的行为，并规划最慢目标造成的日志保留和空间压力。

发送到消息系统时，还需约定消费者如何处理快照、事务边界与重复事件。

## 试点评审清单

| 环节 | 需要确定 |
| --- | --- |
| 范围 | 业务库表、同步用途、敏感级别、可接受维护窗口 |
| 环境 | 数据库确切版本、驱动、JDK、网络、账号、磁盘与备份 |
| 正常链路 | 全量、增量、字段值、延迟和积压 |
| 故障恢复 | Worker 中断、目标停机、SQL 错误、日志保留与恢复 |
| 结果记录 | 配置快照、实际证据、未支持项和后续计划 |

项目没有为全部环境承诺统一 TPS 或恢复秒数。按[性能手册](../reference/performance)记录硬件、负载与测量方法，形成自己的评审结论。
