# 以规格、任务与验收推进项目

项目路线图直接读取这次源码快照中的 SDD 需求清单。保留每个需求的稳定 ID、状态、优先级、差距、依赖和验收条件，方便核对当前实现和后续工作。

<Roadmap />

## 如何阅读计划

`DONE` 表示在该清单记录的范围内关闭；`PARTIAL` 表示有基础但整体尚未完成；`NEW` 表示尚待实现。P0/P1/P2 是需求优先级，不是发布时间。

[需求规格](../sdd/spec) · [实施计划](../sdd/plan) · [任务清单](../sdd/tasks) · [验收矩阵](../sdd/acceptance) · [当前实施状态](../reference/implementation-status)

节点目录、共享账号、跨节点会话与审计已提供相应实现和验证记录。可选固定执行节点全局任务、持久命令与只读查询已接入公开运行时，跨入口校验与审阅修复已有指定业务环境验收；完整迁移、容量与故障矩阵仍未完成；详见[多节点部署与恢复](multi-node)及[跨节点任务控制进展](../reference/global-control)。

源端扩展将从当前 MySQL 向更多数据库类型推进，PostgreSQL、Oracle 源已列入规划；其他数据库按适配接口和独立验收逐步扩展。目标适配不会自动带来源端 CDC 支持。

后续方向包含统一任务控制、远端命令、人工恢复、新源数据库、运行时矩阵、迁移切换和发布完善。以各需求的实际状态和候选包证据为准，不将整份计划作为当前功能列表。
