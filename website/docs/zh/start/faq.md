# 常见问题

## 第一次接触数据库同步，从哪里开始？

先看[项目介绍](introduction)理解源、目标、全量和增量，再按照[快速开始](quick-start)创建一条小规模链路。日志、复制与快照权限由熟悉数据库的同事协助核对。

## 需要修改原业务代码吗？

MySQL 增量从数据库变更日志读取，通常不用在业务代码里加入同步逻辑。仍需满足日志与权限条件，并评估全量读取对源库的影响。

## 可以同步到已有数据的目标吗？

首次目标要求空表或空 schema。非空接管需要显式计划，当前不自动合并或清空已有业务数据。

## 恢复会跳过失败事务吗？

不会。修复错误原因后，恢复操作会重试原事务。需要比较或修复数据时，使用独立的[数据核对流程](data-validation)，由管理员审阅后执行。

## 为什么一个目标出错，其他目标还在运行？

V3 分别投递与确认目标，错误可以按目标隔离。最慢目标仍会限制日志回收，空间不足时可能使采集进入背压等待。

## 登录刷新和控制器重启有什么区别？

浏览器会话可在有效期内恢复。单控制器内存会话在服务重启后需重新登录；启用共享账号和会话配置时，可按相应部署条件恢复访问。具体设置请查看[账号与使用权限](access)或联系部署管理员。

## 本网站会收集数据库账号吗？

本站是静态介绍与文档网站，不需要数据库密码或管理令牌。实际控制台运行在自行部署的服务环境；站内搜索读取本站的静态文档索引。

## 怎样反馈问题？

在[核心仓库](https://github.com/rivomesh/rivomesh/issues)提交同步与连接器问题，在[官网仓库](https://github.com/rivomesh/rivomesh.github.io/issues)提交网站问题。提供确切版本、复现步骤、预期和实际结果，以及脱敏后的配置和错误摘要。
