# 查看状态与日常操作

同步任务启动后，先看它处于哪个阶段，再看目标是否在持续处理。不要只用“进程还在运行”判断数据已经同步完成。

## 看懂常见状态

| 看到的情况 | 表示什么 | 建议操作 |
| --- | --- | --- |
| 全量同步中 | 正在读取来源已有数据 | 等待完成，关注读取进度和目标错误 |
| 增量运行中 | 持续处理来源后续变化 | 观察进度是否前进、积压是否持续增大 |
| 某个目标暂停 | 该目标遇到需要处理的问题 | 查看该目标错误，修复后使用对应恢复入口 |
| 共享任务暂停 | 任务被明确暂停，备用节点也不能直接接管 | 核对暂停原因后由有权限人员恢复 |
| 本机 Worker 停止 | 当前机器的工作进程已停止 | 检查其他节点和共享状态，不能据此断言全局已停 |

截图为界面示例。实际状态以你所登录环境中的任务详情为准。

## 每天检查什么

1. 任务是否处于预期运行状态。
2. 全量进度、积压和各目标确认位置是否持续变化。
3. 是否出现新的 SQL 错误、连接失败或磁盘空间告警。
4. 来源的 binlog、WAL 或 Oracle 归档是否足以覆盖停机和追赶。PostgreSQL 还需要关注复制槽保留的 WAL 和源库磁盘空间。
5. 近期操作记录是否符合预期，是否需要跟进失败的校验或修复作业。

积压不一定立即表示故障。先观察趋势，再检查目标处理速度、网络和资源。各目标独立确认，某个目标正常并不代表其他目标也已追平。

## 停止、暂停和恢复如何选择

- **停止本机 Worker**：只停止当前机器进程。存在备用节点时，应同时核对共享任务状态。
- **暂停共享任务**：用于明确暂停整条共享任务，并阻止备用节点接管。无法联系的目标仍需核实隔离结果。
- **恢复此目标**：修复单个目标的 SQL 错误后，按该目标的当前错误状态重试。
- **修复后恢复**：处理任务级问题后使用。它不会自动清除其他目标自己的 SQL 暂停。

恢复是重试原事务，不会自动跳过失败记录。对于受限账号，看不到操作入口时，请先联系管理员确认授权。

全局模式的操作通过持久化命令交给所属 Agent。收到 HTTP 202 后，在控制台用原请求 ID 查询回执；Agent 失联时，命令可能继续显示等待或未知。

## 配置需要调整时

管理员可以使用配置编辑和版本恢复功能。修改前记录原版本，确认是否影响任务身份、目标映射或已有状态；需要重建或迁移的配置不能直接当作普通编辑处理。

## 查看跳过后的增量进度

处理覆盖水位包含显式跳过事务，连续应用水位停在首个缺口之前，历史复核后也不前移。消息确认覆盖发布，消费者处理进度需独立追踪。详见[缺口复核与水位](../reference/gap-verification)。
