# 核对数据与修复差异

日常运行时，进度表示同步工作进行到哪里；数据校验用于比较来源与目标的实际内容。校验报告对应历史检查点，不能理解成“此后一直完全相等”。

## 先确认适用范围

当前管理界面的逐行校验和修复，首批真实验证目标为 **MySQL 8.4 / PostgreSQL 17**。消息和分析目标不使用这套流程，其他数据库产品与模式需要独立确认。

开始、取消和继续校验，以及生成与执行修复计划，都需要管理员权限。只读账号和操作员可按授权查看摘要。

## 第一步：发起数据校验

1. 完成全量同步，启动本机 Worker，确认任务处于 RUNNING，选定目标能够追平。
2. 进入任务详情的“数据校验”，选择需要比较的目标。
3. 由管理员设置锁等待、读取时间和暂存预算。
4. 点击“开始逐行校验”，在操作记录中查看进展。
5. 完成后打开报告，查看各表的来源行数、目标行数、缺失、多余和变更。

建立共同检查点会短时影响源库写入，请提前安排时间。校验完成后需要核对任务状态并显式恢复；校验不会自动修复数据。

## 第二步：理解差异

| 结果 | 含义 |
| --- | --- |
| 缺失 | 检查点时来源存在、目标缺少的记录 |
| 多余 | 检查点时目标存在、来源没有的记录 |
| 内容变更 | 对应记录存在，但字段内容不同 |

管理员可以按表查看差异，并显式展开原始值。原始值属于业务数据，应按组织的数据访问要求使用。

## 第三步：审阅后修复

任务保持暂停，显式选择需要修复的目标和表，再生成计划。审阅目标、表、差异数量和预算，确认后执行；完成后检查逐表结果，再显式恢复同步。

修复会修改目标业务数据。取消不能撤销已经提交的表；失败或取消后，应重新审阅同一计划并核对已提交结果。带外键、触发器或其他不支持依赖的目标会被拒绝，不能通过移除保护强行执行。

## 中断或取消怎么办

取消校验不等于恢复同步。完整来源数据已经保存时，可以使用“继续目标比对”；尚未完成来源读取且读取视图已经丢失时，需要检查并恢复任务后重新校验。

详细限制和操作参数见[校验参考](../reference/managed-validation)与[修复参考](../reference/managed-repair)。业务切换需要独立方案，不能仅凭校验或修复成功直接接管写入。

## 在审阅跳过后复核缺口

在 PostgreSQL / MySQL 指定档案中，修正差异后重新运行完整共同点校验，从结果匹配的报告选定缺口并生成计划。管理员审批后重新扫描，回执只覆盖已审阅历史截面，任务继续保持暂停。详见[数据缺口复核](../reference/gap-verification)。
