# 什么是 RivoMesh？

RivoMesh 用来把 MySQL 中的数据持续同步到其他系统。它先处理已有数据，再根据变更日志传递后续新增、修改和删除，适合信创数据库改造验证、建立数据库副本、为分析系统准备数据和向消息系统分发业务变化。

## 一条链路包含什么

**数据源 → 持久日志 → 同步目标**。当前实际采集源为 MySQL；目标可以是关系数据库、分析系统或消息队列。目标产品、模式和版本不同，数据确认与恢复协议也不同。

| 概念 | 含义 |
| --- | --- |
| 全量同步 | 读取源库中已有的数据，准备目标初始数据 |
| CDC 增量同步 | 从 MySQL binlog 捕获新增、修改和删除 |
| 同步任务 / Pipeline | 源、库映射、日志和目标的组合 |
| 持久日志 / Journal | 保存事件与进度，支撑重启、重试和独立目标确认 |
| 断点恢复 | 根据已安全保存的进度继续处理，不把重新启动等同于重新全量 |
| 多目标分发 | 一个逻辑源映射到多个目标，各目标分别记录确认位置 |

## 通过什么方式使用

可使用 Web 向导、YAML 配置或 CLI。Web 控制台用于创建任务、检查连接、启停、查看阶段与积压，以及授权范围内的恢复和数据质量操作。Java 服务独立运行，源端采集不依赖 Canal Server。

## 信创与多源扩展

可向 openGauss、达梦、金仓、GBase 8c 等国产数据库同步数据，按指定版本和模式开展[信创适配验证](xinchuang)。当前采集源为 MySQL，PostgreSQL、Oracle 源仍在规划；源适配接口可继续扩展其他数据库。每种源的全量、日志与断点需要独立实现和验收。

## 多节点部署

多个节点可以共享节点目录，并按配置统一账号、会话和审计。同步执行的主备恢复依赖持久日志和租约；可选固定执行节点的全局任务操作已接入，管理与 Agent 分离已有首批验收，自动跨 Agent 接管与完整高可用矩阵仍待扩展。详见[多节点部署与恢复](multi-node)。

## 当前适合怎样开始

当前是 `0.1.0-SNAPSHOT` 发布前版本。先选一个测试业务库和独立空目标，跑通全量、增量、值比对及重启恢复，再扩大范围。生产环境的版本、对象、权限、容量和故障场景需要按自己的环境验收。
