# 常见故障处理

先记录任务标识、故障时间、来源与目标类型、错误摘要和最近一次配置变更，再按下面的现象排查。公开反馈时请移除密码、令牌和业务原始值。

## 控制台打不开或无法登录

- 在部署机器本机访问 `http://127.0.0.1:8080`，确认服务已启动。
- 默认只监听本机，其他机器访问需要部署人员配置受控的远程入口。
- 确认使用当前有效的令牌或账号，令牌不能放进 URL。
- 远程登录反复失效时，检查 HTTPS、Cookie 与 Origin 配置，详见[浏览器会话说明](../reference/browser-sessions)。

## 连接检查失败

| 提示或现象 | 优先核对 |
| --- | --- |
| 连接超时或拒绝 | 主机、端口、网络、防火墙；容器中的地址是否可达 |
| 认证失败 | 用户名、密码、来源地址限制、环境变量是否传入服务 |
| 来源对象不可读 | 库名、读取权限、复制权限、GTID 和日志格式 |
| 检查通过但启动失败 | 建表、快照读锁、目标空表及运行时权限 |

不要用“能在个人电脑连接”代替部署机器的网络检查。

## 目标因 SQL 错误暂停

1. 打开任务详情，查看出错目标、表和错误摘要。
2. 排查字段类型、约束、权限、对象结构或目标资源问题。
3. 修复原因后，使用该目标的恢复入口重试原事务。
4. 确认目标进度重新前进，并检查后续积压。

重启进程不能绕过共享暂停。不要手工删除队列、修改 GTID 或伪造成功状态。

## 积压持续增长

分别检查各目标，确认是全部变慢还是单个目标异常。核对网络、数据库负载、磁盘容量、锁等待与源数据变化速度。容量和性能需要结合本环境测量，不宜套用固定 TPS 数值。

## 停机后无法续传

先保留原配置、日志、状态表和控制器目录。若来源已经清除了必需的 binlog，任务会拒绝继续；应由数据库管理员评估可用日志及重新初始化方案，不能直接跳到新的位置。

查看[备份与恢复](backup)和[恢复规则参考](../reference/recovery)，确认哪些数据必须作为同一恢复单元保留。

## 仍无法解决

向[核心项目提交问题](https://github.com/rivomesh/rivomesh/issues)，附上版本、部署方式、数据库产品与版本、复现步骤、脱敏后的错误和配置。仅网站排版或文档问题请提交到[网站仓库](https://github.com/rivomesh/rivomesh.github.io/issues)。
