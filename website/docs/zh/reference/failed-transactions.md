# 失败事务诊断与人工恢复

[English](/docs/en/reference/failed-transactions.html) · [SDD实施契约](/docs/zh/sdd/design-failed-transactions.html)

当前界面支持目标故障阶段摘要、增量原事务重试、快照分块恢复及[管理员事务审阅](/docs/zh/reference/failure-review.html)。有界暂停事务检查和[持久证据](/docs/zh/reference/failure-evidence.html)已接入界面原始/规范化事件分页；人工跳过和独立补数据仍未开放。共同校验点的报告驱动修复见[托管修复](/docs/zh/reference/managed-repair.html)，不要将其当成失败队列的补偿功能。

## 界面操作

1. 打开任务详情，找到暂停的目标。记录目标标识、错误版本、确认序号、错误码、故障阶段及可用的失败事务序号。
2. 根据阶段检查原因。目标连接/元数据激活：检查地址、凭据、权限及目标元数据。目标应用：检查类型、约束和目标数据。映射/历史结构：检查映射和对应历史结构。提交核对：先核对目标凭据和日志 ACK，不手工推进位点。
3. 修复原因后点击“恢复此目标”。请求绑定该目标错误版本：增量阶段重新投递完整原事务，快照阶段核对并继续分块断点；旧版本请求会拒绝。源任务的全局恢复与目标恢复是不同操作。
4. 查看该目标是否追平，并执行合适的一致性校验。恢复请求被接受、进程存活和 ACK 追平，都不能单独证明业务接管完成。

目标激活失败可能尚未定位任何事务，此时不展示虚假的失败事务序号。旧版本留下的暂停没有可信阶段时显示“未知”。阶段记录损坏时显示诊断不可验证；原事务检查也会拒绝。SQLState相同的激活失败与应用失败不能混为同一种故障。

只读阶段摘要可以通过已有全局任务查询从不同控制入口查看。摘要只包含阶段、序号及故障epoch，不包含事件ID、行值、SQL或连接凭据。权限仍按既有任务查看授权；原始行值不加入普通任务状态接口。首次准备和快照阶段已增加专用诊断；旧记录仍可能未知，完整源连接/读取/解码/DDL阶段诊断待补。真实故障验证见[快照证据](/docs/zh/evidence/baseline.html)。

本轮内部检查、双入口实际SQL故障/重启及五JRE基础契约的[验收范围与证据](/docs/zh/evidence/baseline.html)已归档。它不等于人工恢复全部完成。

## 内部事务检查的边界

`Journal.inspectFailure(subscription, expectedErrorGeneration, maximumBytes)`只读已暂停订阅的下一完整事务。读取绑定日志世代、当前epoch、配置指纹、错误版本及ACK，校验原始与已存在规范化内容的摘要；不会连接或激活业务目标，不会生成缺失的规范化内容、改变无主键身份或推进ACK。没有完整事务时明确拒绝，不根据后续事件猜测边界。

原始与规范化负载共享最多4MiB的读取预算；诊断记录另有16KiB上限。存储长度检查和有界字符流共同阻止超限，UTF-8按字节复核。尚未消耗的规范化预留空间可能使保守长度检查提前拒绝。超限不返回可批准的部分事务；大型事务的流式审阅仍待实现。

这是底层检查接口，不是管理员执行计划；管理端另经[持久创建、授权及审计](/docs/zh/reference/failure-review.html)开放。返回对象本身不具备持久授权/批准效力。暂停ACK会保留当前日志；恢复后可能回收，所以不能把内存对象当成长期证据。界面使用已保存证据；目标原生断点核对、审批和缺口台账仍待完成。结构准备/快照失败不能当作下一条失败增量事务读取，会明确拒绝。

## 常见问题

**能像MySQL从库一样跳过一条错误吗？** 当前不能。源事务可能跨表且含多个事件，未来跳过按完整事务、明确目标执行。需要原生SKIP凭据、日志缺口记录和幂等恢复；直接修改ACK、GTID或删除日志会破坏恢复保证。

**目标可能已经提交，网络却报错怎么办？** 自动投递会核对目标断点、完整事务ID和目标投影摘要，再补日志ACK。无法确认时停止/重试，不把它视为可跳过的未提交事务。人工补偿也必须先完成这个核对。

**修改源库数据能修复旧错误事务吗？** 后续源更新是新事务，不会改写已持久化的旧事件。需要修复旧事务失败的目标条件，再重试；未来的补偿计划也必须基于旧事务镜像和目标当前状态。

**重启会清除错误吗？** 不会。暂停、错误版本和阶段记录持久化；重启仍需要显式恢复。另一个目标可以继续投递，但失败目标会保留日志并消耗容量。

**阶段未知可以直接按应用错误处理吗？** 不可以。没有阶段的旧记录、阶段证据损坏或源采集/解码失败都不构成已知可跳过事务。先检查原日志、源保留范围和历史配置。

**binlog已被清理或无法解码怎么办？** 不能用目标恢复按钮补造源历史。应恢复所需日志、选择包含所需历史的合格源，或按新基线计划重建；受控缺口恢复与所有受影响目标的缺口追踪仍在RC-04/08待实现。

**可以直接在目标库补数据吗？** 现有同步假设目标由同步服务独占写入。无计划手工修改可能影响约束、无主键内部身份和后续重放。界面类型化补数、漂移检查和原子补偿凭据属于RC-06/07，尚未开放。
