# 失败事务证据存储

[English](/docs/en/reference/failure-evidence.html) · [实施契约](/docs/zh/sdd/design-failure-evidence.html) · [故障处理](/docs/zh/reference/failed-transactions.html)

存储与捕获接口已接入[管理界面审阅](/docs/zh/reference/failure-review.html)，包含管理员/任务权限、审计及协议5门禁；本页解释底层文件与限额。保存成功不代表目标未提交，也不构成跳过、补偿或业务接管批准。早期内部接口验收不等于当前全部界面档案，最新范围见[验证记录](/docs/zh/evidence/baseline.html)。

## 保存内容与身份

每条不可变证据包含审阅ID、原请求ID、操作者/时间、任务ID、原执行节点和目录身份、配置修订、日志世代/epoch、错误版本、ACK和完整事务摘要。原始事务、已经存在的规范化事务，以及事件引用的历史表结构一起保存。未规范化时明确保留该状态，不在审阅时生成规范化结果或改变无主键身份。

历史结构按事务实际引用的`tableId/schemaVersion`查询，不扫描整个目录；缺失、校验失败或结构身份不符时拒绝捕获。已发布证据不依赖原日志继续保留；原日志回收后仍可读历史证据。它是当时的观察，执行前仍需重新核对任务、配置、位点、目标凭据和目标漂移。

`FailureEvidenceCapture.capture`先查同一审阅ID的已保存记录，匹配原请求、操作者、配置修订、目标及错误版本后返回原结果；因此重试不要求原日志仍存在。修改同一ID的内容、身份或请求参数会拒绝，不覆盖旧证据。

## 私有文件和配额

- 默认目录预算256MiB、最多1000条，每条最多8MiB；通过内部`FailureEvidenceStore.Limits`配置。预算统计已保存文件、密钥、权威记录和遗留临时文件的大小，不代表数据库、磁盘块或备份的全部物理占用。
- 目录0700，创建的证据、密钥、权威文件及锁文件0600。符号链接及其父路径会被拒绝；安装目录和备份也应保持相同私有权限。
- `evidence.key`是独立随机32字节密钥，用于HMAC校验；`authority.json`绑定原任务/节点/目录身份。证据还校验完整内容摘要，严格拒绝截断、重复字段和尾随JSON。
- 保存使用跨进程锁、私有临时文件、文件fsync、原子发布及目录fsync。重复发布不能突破配额。锁忙明确报错，调用层应按原请求重试。
- 配额满时拒绝新增，保留旧证据；当前没有自动删除、过期回收或密钥轮换入口。中断遗留`.pending`文件不作为有效证据读取，也不会被静默删除，仍计入预算。硬盘故障及实际断电验收仍需补充，不能把单元测试当成已完成。

## 摘要与分页

内部摘要返回身份、阶段、位点、摘要和事件数量，不返回行镜像或SQL。原始/规范化事件分别分页，每页最多100个事件和256KiB。单个事件放不下时整次拒绝该事件，不返回截断镜像。每页携带不可变证据摘要及后续索引，方便关联同一完整事务。

事务读取仍受原始与规范化合计4MiB预算，历史结构合计2MiB预算；大事务流式审阅尚未完成。文件预算与事件页预算是不同限制，不能通过增大分页绕过事务读取限制。

## FAQ

**密钥丢失能生成一个新的继续读取吗？** 不能。存在证据/权威记录时丢失密钥会拒绝初始化；错误密钥也无法通过签名检查。恢复时需要一起恢复密钥、权威记录、证据和原目录身份，并恢复私有权限。

**能复制到另一个Agent自动接管吗？** 不能。原owner及目录身份变化会拒绝。明确的数据迁移、授权和断点接管协议仍待实现。

**保存证据是否固定了目标提交状态？** 没有。当前捕获不连接或激活业务目标；不会假设目标未提交。原生断点核对与提交领先ACK的人工处理属于RC-05。

**文件可以直接作为跳过计划吗？** 不可以。还需要原生SKIP/补偿凭据、当前状态重验、审批、缺口台账和幂等恢复。当前没有人工跳过或独立补数据入口。
