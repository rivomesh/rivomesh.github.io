# 配置编辑与版本历史

English：[Configuration revisions](/docs/en/reference/configuration-editor.html)。

控制台已接入不重置断点的配置编辑、凭据轮换和版本恢复。旧 Java 8 候选包的 MySQL 8.4 → PostgreSQL 17 链路已验证目标密码轮换、恢复历史版本和控制器重启后续传；详细范围见[验收记录](/docs/zh/evidence/baseline.html)。

仅 ADMIN 可以读取/编辑配置及版本历史。GET 返回的密码、令牌、含凭据的URL/连接选项都替换为不透明引用，不返回已保存值或ENV引用。保留引用即保留原值；替换为新字符串可轮换，适配器允许时可用null/空串清空。引用绑定任务、版本、字段位置及目标身份，不能跨目标搬移；重启或并发修改后可能需要重新读取。保存响应不回显配置。

先停止本地任务；已完成暂停的任务也可编辑。运行中的Worker、待完成操作会阻止保存。预览只返回变化路径及是否需要迁移，不显示凭据新旧值。本流程要求任务ID、同步指纹和物理日志位置保持不变；映射、产品、语义配置、源库列表和日志存储位置变化需要另行迁移。v2连接URL包含凭据时，它仍属于旧指纹，普通轮换应使用独立password字段；本编辑器不会重写旧断点身份。保存保留STOPPED/PAUSED意图，检查连接后再显式启动/恢复，不绕过共享暂停和错误代次。

每个提交版本在 `dataDirectory/config-versions/<taskId>/` 保存不可变的私有YAML及元数据，记录父版本哈希、操作者、请求ID和时间。controller注册表以原子指针选择唯一版本；未被引用的暂存文件不属于已提交历史。任务YAML和worker-config文件成为可修复投影，Worker从已提交版本启动，启动前核验内容。投影缺失可在重启后重建；已提交版本损坏会阻止任务，不回退到旧文件。应协调备份注册表、版本目录、原任务文件和日志。

原有外部配置文件在首次通过本流程编辑前，保留原来的启动加载方式。界面创建/编辑后的文件由控制器管理，手改投影不会修改已提交版本，应使用编辑器/API。独立CLI任务文件不变。历史版本会保留旧凭据，必须保护整个私有目录；版本和孤立暂存文件的自动清理尚未实现。

历史每页20条，使用签名游标。恢复先预览变化路径，再新增一个链接当前版本的恢复版本，不删除历史、不回退数据库断点。控制器重启或配置头变化后，旧游标/历史引用可能失效，重新读取即可。请求去重仍绑定操作者与角色，其现有有界保留和配置历史分开管理。

版本哈希用于相对于注册表检测损坏，属于配置溯源，不能抵御有权限重写全部文件的系统管理员。拒绝/认证事件和异步结果现由独立[安全审计](/docs/zh/reference/security-audit.html)记录，支持保留/导出。[精确任务授权](/docs/zh/reference/task-authorization.html)已实现；外部不可变锚点及账号管理仍待完成。

## 界面操作

1. 以 ADMIN 登录并选择任务，点击“配置和历史”。运行中可以查看、准备修改，保存前先停止本机 Worker 或等待暂停完成。
2. 修改账号、全量分块行数、轮询或重试间隔。密码/令牌选择“保留当前值”“替换”或“清空”；已保存的值始终隐藏。高级 JSON 支持其余字段，新输入的凭据在该文本框中可见。
3. 点击“预览变化”，核对字段路径。出现需要迁移的提示时不能覆盖当前任务；同一字段继续修改后必须重新预览。
4. 保存新版本后执行“检查连接与对象”，再显式启动或恢复任务。保存本身不启动，也不清除共享暂停或失败事务。
5. 在“已提交版本”中选择版本，先预览恢复变化，再保存恢复版本。恢复后同样检查连接；数据库密码已改变时，旧版本的旧凭据可能无法连接。

退出、关闭编辑框会清除界面草稿；敏感历史版本仍保存在私有磁盘目录。超过20条历史可继续加载，任务操作列表的40条保留上限不截断配置版本历史。

## FAQ

**重启后需要重新全量吗？** 普通凭据/运行参数编辑保留同步身份和日志位置，真实库验收保持原流及快照身份，继续应用增量。修改身份、映射或日志位置会要求迁移。

**配置文件被手改或删除怎么办？** 已托管任务的投影会从已提交版本修复。不要用手改投影覆盖配置。版本目录/注册表损坏时需恢复一致的备份，服务会阻止启动，不能通过删除版本绕过检查。

**报版本冲突、历史引用失效怎么办？** 重新加载当前配置或历史，核对他人的修改后再次预览。控制器重启、配置头变化会使旧引用失效。

**旧 Worker 无法停止怎么办？** `WORKER_STOP_UNCONFIRMED` 会阻止配置更新。先确认并处理旧进程；不能启动第二个配置来绕过停止确认。

**保存后投影仍待修复？** 版本已经提交。检查持久目录空间、权限及同名目录冲突，等待控制器重试；保留注册表、版本文件及日志。

## API

- `GET /api/tasks/{id}/configuration`：脱敏配置、乐观版本。
- `POST .../configuration/validate`：`{config, expectedRevision}` 或YAML格式。
- `PUT .../configuration`：同上，加 `X-Request-ID`，提交不可变版本。
- `GET .../configuration/history[?cursor=...]`：元数据、恢复引用。
- `POST .../configuration/restore/validate`：`{reference, expectedRevision}`。
- `POST .../configuration/restore`：同上，加 `X-Request-ID`。

VIEWER/OPERATOR 在读取配置或修改正文前即被拒绝。历史只返回元数据。并发/陈旧编辑返回409，格式错误或过大/过深的文档返回400。保存成功但非权威投影尚未写出时，会返回 `configurationProjectionPending=true`；应保留版本目录、修复空间/权限，控制器会重试投影，不会以删除历史掩盖未完成写入。
