# 失败事务持久证据

RC-02/05/09 · 2026-11-17 · [English](/docs/en/sdd/design-failure-evidence.html)

本设计接续[恢复契约](/docs/zh/sdd/design-failed-transactions.html)，不开放跳过或补偿写入。

- 原始证据位于原执行节点私有目录，以不可变审阅ID保存。内容绑定任务ID、原owner及目录身份、配置修订、操作者、时间、日志世代/epoch、错误版本、ACK、完整原始/规范化事务摘要；保留解释事件所需的历史结构。文件不是当前执行授权。
- 原始值只保存在私有文件，目录0700、文件0600。禁止符号链接、越界路径和超限读取。独立随机密钥校验HMAC；密钥丢失、签名/摘要损坏、身份不符均拒绝，不能生成新密钥后静默接受旧证据。备份必须包含密钥和目录身份。
- 同一审阅ID的重复请求返回原记录；身份、请求内容或目标不同则冲突。写入采用私有临时文件、fsync、原子发布及目录fsync；进程中断后只能读到完整原记录或没有记录，不能读到半份有效证据。跨进程锁保护配额和发布。
- 每条与整个证据目录分别设字节/数量配额。配额满时明确拒绝，不自动删掉旧证据；未解决缺口不得静默回收。临时文件和物理空间边界需要在运维中说明。
- 当前事务检查结果不是长期证据。必须先完成持久化和校验，才返回可审阅ID；以后即使原日志被回收，已保留证据仍可按原摘要读出。缺失历史结构不能形成可执行计划。
- 摘要不含行值或SQL；原始/规范化事件采用有界分页，单事件超页限额时明确拒绝，不能截断镜像再批准。审阅缺少规范化内容时明确标注，不在读取时更改日志或无主键身份。
- 接入全局界面前，新请求必须有能力/协议门禁，旧Agent不能消费未知恢复命令。创建证据采用持久操作，按原请求/审阅ID恢复；查询仍重验共享权限及审计。跨Agent搬迁不由文件复制隐式实现。

验收至少覆盖：重启后读取、相同ID幂等/冲突、内容和密钥损坏、目录身份变化、符号链接、配额不删除旧证据、并发发布、写入中断、摘要无原始值、分页边界，以及日志回收后仍可审阅。目标原生断点核对与执行前漂移检查另属RC-05；即使证据完整，也不能据此断言未提交或批准跳过。

## 界面与协议接入（限定档案已验收）

共享全局控制显式配置`cluster.recoveryReview: true`后使用控制协议5；要求sharedTasks/sharedAccess。默认关闭时保留原协议3/4和已有请求，创建/查询新证据在持久命令及owner查询入口拒绝。升级要求旧成员正常STOPPED，过期租约不等于正常停止；协议5建立后旧模式拒绝加入。单机入口不涉及旧Agent，仍需管理员权限。

创建使用`FAILURE_REVIEW`持久动作，沿用目标及错误版本，执行前保存审阅ID及原配置修订。查询为摘要GET与原始/规范化事件POST，绑定原执行目录，限额256KiB/100事件，重验权限并审计；不会自动恢复任务。全局操作视图必须保留审阅ID，不能只返回已成功状态。UI默认展示摘要，原始值需显式点击；退出后关闭审阅内容，晚到响应不得复活旧会话。
