# CP-01/02/03：共享控制状态与节点目录

[English](/docs/en/sdd/design-control-store.html)。此文先固定协议合同，再实现和验收；节点目录完成不代表全局任务控制完成。

## 存储和身份

保留默认单机本地模式。显式启用 `cluster` 后使用单独 SQL 控制命名空间，首批为 PostgreSQL/MySQL；H2 用于协议测试。共享控制状态与业务目标/CDC 日志是不同职责，可按独立命名空间复用 SQL 实例。连接使用专用凭据、限时连接/查询，不把 URL、凭据或业务数据返回页面。

`rmc_cluster` 记录 clusterId、协议格式和统一租约期限；同集群不兼容设置拒绝启动。`rmc_node` 记录稳定 nodeId、进程 incarnation、注册 epoch、数据库时钟心跳/租约、退出状态及版本/JVM/架构/容量。注册容量在集群行锁下检查；活动 nodeId 不允许另一进程覆盖。心跳和退出均校验 incarnation/epoch；旧进程不能续租或改写新进程记录。数据库时间是失联判定依据，客户端时钟不参与授权。

`rmc_node_task` 第一阶段仅保存白名单任务观察：任务ID、控制修订、期望状态、Worker状态、观察时间。它不是全局任务权威表，也不授权恢复/调度。重复 taskId 可在观察中显示冲突；不能靠该表声称全局唯一或执行接管。全局配置/命令、幂等回执、owner fencing、权限/审计与跨控制器会话在 CP-02/03/04/05/07 和 SE-04 后续实现。

## 节点视图

管理入口使用数据库一致快照查询同一节点目录，返回服务器观察时间、最近心跳、租约到期、HEALTHY/STALE/STOPPED、node epoch、真实版本/JVM/架构/CPU/堆和配置容量。节点及任务观察按节点ID游标分页，节点数量和每节点任务数有上限。过期记录明确标识，不删除成“没问题”，目录不可达返回503，不能把缓存视图当成健康。

第一阶段只向 ADMIN 提供全局节点/任务观察，保留 VIEWER/OPERATOR 原任务权限。页面清楚标识节点目录与本机任务操作范围；后续远端控制接入后再改变任务视图语义。独立节点配置/密钥/日志路径不写入目录。节点租约不替代现有 CDC/目标 Worker fencing。

## 生命周期及测试

启动建立/检查控制 schema，注册节点，启动有界独立心跳线程；关闭停止心跳并以本代身份标记 STOPPED。断电/kill 后由数据库租约判为 STALE。控制库中断时 readiness 失效，目录请求503；本阶段既有 Worker 继续遵循其同步日志租约，尚不接受全局接管命令。

验收包括：两个独立本地目录的服务读取同一节点目录；并发注册、活动ID碰撞、过期替换、旧进程续租/退出拒绝；数据库时间与容量；分页和无凭据投影；HTTP权限；真实 PostgreSQL/MySQL 双节点启动、kill/重开及控制库存储中断恢复；最新UI、制品及双语运维说明。目录观察通过后只关闭 CP-01，不关闭其他集群条目。
