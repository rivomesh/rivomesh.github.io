# SE-04 / CP-05：共享身份、会话和审计合同

[English](/docs/en/sdd/design-shared-access.html)。此合同的SE-04范围已验收，CP-05部分完成；见[证据](/docs/zh/evidence/2026-11-16-shared-access.html)。

通过显式 `cluster.sharedAccess` 选项启用SQL共享账号权威、会话与审计。默认单机/目录档案不改变；该选项并不把本机任务页自动变为全局控制。全局任务与命令另由CP-02/03实现。

首次初始化可导入当前已验证的托管账号快照，或以部署账号引导共享目录。保存独立的共享存储身份，并在本机控制状态中持久绑定cluster/store身份，升级状态格式，旧程序或关闭共享选项时拒绝回退为旧本地授权。共享库缺失/身份变化/目录冲突拒绝启动；已存在共享目录不被启动配置中的旧令牌覆盖。迁移前备份本地状态和审计；原有历史保留在本地，并记录导入锚点，不伪造同一条历史链。

每次认证、权限重验、账号修改和会话恢复查询共享权威，不以本地缓存或黏性会话代替一致性。账号变更、全目录会话撤销和账号变更审计在同一SQL事务提交；保留修订、请求ID及回执检查。创建会话时锁定账号修订，拒绝已撤销的身份快照。

Cookie仍为不可读的随机会话ID；共享库只保存其摘要及最小身份/CSRF/期限数据。期限使用数据库时间；相同共享会话策略在所有成员核验，跨节点时钟差不延长权限。控制器关闭仅释放本地连接，不清空其他节点仍在使用的共享会话。节点重启、请求从A转到B可恢复；退出/停用/轮换后B拒绝旧会话。API Bearer、Origin/CSRF规则保留。

共享审计采用数据库锁定的序号/哈希链与保留锚点。HTTP及新任务审计按同一事件ID重试，不能因跨节点重试重复写或忽略不同载荷。原本机持久outbox在共享审计确认后才清理；故障时拒绝宣称已经完成。导入前本地历史保留并单独导出，不重写旧载荷。

验收：两个独立控制目录、共享SQL、A登录/B恢复；杀掉A后B继续认证；在B退出/轮换/改权限，A和重开节点拒绝旧凭据；共享存储中断不得回退到本地账号或内存会话；目录导入、存储身份丢失和旧程序回退拒绝；并发账号/会话/审计、期限/容量和幂等事务检查；真实PG/MySQL档案、UI与双语恢复说明。完整CP-05还包括任务密钥最小下发，不能只凭共享账号标为全部完成。
