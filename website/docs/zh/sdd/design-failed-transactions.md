# 失败事务恢复契约

RM-SDD-001 · RC-01—RC-10 · 2026-11-17 · [English](/docs/en/sdd/design-failed-transactions.html)

本契约约束接下来的人工恢复实现，不代表跳过或补数据已经验收。各项完成状态以 requirements.json 为准。

1. 故障阶段由执行位置记录，不根据 SQL 异常类推断。目标激活、日志读取、规范化、目标投影、目标凭据核对、目标应用和日志确认是不同阶段。旧记录没有阶段时显示 UNKNOWN，不能推测为可跳过。
2. 暂停订阅及其失败诊断同一日志事务提交，绑定错误版本。重复暂停保留首次故障；重试后再次失败生成新版本。诊断不保存异常消息、SQL、连接串或业务行值。
3. 检查只读取已暂停订阅的下一完整事务，原子绑定订阅错误版本、ACK、日志世代、epoch、配置指纹和内容摘要。检查不确认事务，不激活目标、不规范化事件，也不修改无主键身份。没有下一事务、历史丢失或内容损坏必须明确拒绝。
4. 原始及已存在的规范化内容一起受读取配额限制。超限整次拒绝，不截断为可批准的事务。读取有字符/字节上限，不能仅信任可损坏的存储长度。这里的初始内部接口上限为 4 MiB，不代表大事务流式审阅已经实现。
5. 读到的内容仅是当前快照，不是执行凭证。授权、私有持久证据、目标投影摘要、原生断点核对和保留策略完成前，不开放执行入口。暂停 ACK 保留当前日志；恢复并回收后，内存中的检查结果不能作为历史凭证。
6. 执行计划必须绑定原始 owner/目录身份、配置修订、日志世代/epoch、错误版本、ACK、完整事务和目标断点。目标已提交领先 ACK 时，先核对完整内容并恢复确认。断点不明或摘要不符时拒绝跳过/补偿。
7. 跳过只针对一个目标的完整事务。目标原生 SKIP 凭据与安全进度原子提交；日志 ACK 与缺口记录原子提交。重启通过原始请求核对两端凭据，不能重复跳过，也不能把 SKIP 当 APPLY。开放前必须升级数据格式/能力协议，使旧程序拒绝错误解释新断点。
8. 补偿计划显示类型化前后值及影响身份，执行前重验目标漂移；数据与原生补偿凭据原子提交。补偿不改写源日志，不自动重置源位点，不自动恢复任务。
9. 缺口区分待修复、接受丢失及经验证关闭。安全覆盖进度与真实已应用进度分别展示；其他目标不隐式跳过。未解决缺口及待审证据不能静默回收，容量不足时背压。
10. 管理界面使用跨节点持久请求、共享权限及审计；原始业务值单独授权、分页和限额。新请求类型发布前必须建立旧 Agent 拒绝/能力协商测试。不能只在本机界面实现。

首批验收：目标激活失败不冒充 APPLY；第二个事务应用失败准确定位第二个事务；不确定提交不能批准跳过；暂停检查在重启后读取相同内容；旧版本检查/运行中检查拒绝；原始或规范化损坏、序列丢失、超限、长度伪报拒绝且 ACK 不变；并发恢复/回收不能产生混合快照。后续再逐项补原生凭据、强杀窗口、UI、权限和多目标验收。
