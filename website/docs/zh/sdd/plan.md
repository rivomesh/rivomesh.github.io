## 2. 用户已明确的需求，不再当作可选项

1. 同一平台多节点统一管理，任一管理入口能看到并控制远端任务，不能只聚合几个本机界面。
2. 登录状态刷新后保持；退出、失效和权限撤销仍必须有效。
3. 遇到同步故障，有经审阅的人工跳过、补数据及重试路径；普通自动恢复继续默认不跳过。
4. 源端必须纳入 MySQL5.7/8.0/8.2/8.4、PostgreSQL、Oracle；PG/Oracle从“未来预留”升级为本次承诺范围。
5. Java8/11/17/21/25都要有实际运行证据，不能只看编译级别或镜像标签。
6. 完整中英文文档、场景和FAQ；既有多库显式映射、同源多目标、产品覆盖、可选日志、四类部署和政企迁移目标继续保留。

## 3. 多节点设计提案

建议拆分统一管理入口、共享控制状态、节点Agent/Worker和源日志/目标应用协议。控制元数据、会话和源日志不是同一概念，可在合适SQL实例上分命名空间复用，也可独立部署；不强制所有单机部署新增独立日志服务。

- **统一入口**：Web/API/CLI面向一个逻辑集群。节点ID、任务ID、任务修订和权限在集群范围有明确权威状态。
- **Agent执行**：控制器提交有类型、可去重、带代次的持久命令；当前owner或被授权Agent执行。控制器本机 `ProcessBuilder` 不再是唯一执行通道。远端接口只提供授权生命周期/任务操作，不提供任意主机Shell。
- **命令结果**：区分已接受、排队、执行、确认、失败、拒绝、结果未知。超时或网络分区不能直接显示“已停止”；未知结果需用同一请求ID核对。
- **隔离**：集群注册代次与任务租约/epoch联合验证。旧owner复活或命令延迟到达时拒绝写入，不能仅依赖心跳或副本数。
- **存储位置**：计划、报告、原始事件和密钥使用带归属/校验的引用。若日志或报告仅本地存在，任务需绑定节点/可恢复卷，不能在其他节点只恢复一个游标就继续。
- **HA边界**：单机嵌入式配置继续存在；多控制实例需共享权威状态和会话，或经过验证的等效一致性方案。管理实例退出与Agent执行进程生命周期分离，具体继续/暂停策略写入部署档案。

候选逻辑实体：Cluster、Node（incarnation、心跳、能力、资源）、Task（源/目标、修订、owner代次）、Command（请求ID、权限、期望状态、执行回执）、Session、RecoveryPlan、ConsistencyGap。字段、后端和协议的最终详细设计仍待后续规格增量确认，不能把这些名称当成现有API。

## 4. 登录保持提案

保留已有API令牌能力，浏览器登录后换取可撤销的短期服务器会话；建议使用不暴露给页面脚本的受保护cookie，生产经HTTPS传输，配套CSRF/Origin防护。不能将长期管理员令牌写入localStorage来完成刷新保持。[OWASP会话管理说明](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)。

页面启动先恢复会话及权限，再加载任务；多实例请求共享会话权威状态。退出、账号停用、轮换和权限撤销应触发相应失效。CLI/API Bearer方式继续可用，身份冲突规则需明确。空闲/绝对期限、浏览器关闭后是否记住登录、是否接入OIDC属于策略配置；本次不擅自把某个时长或双人审批定为用户已确认要求。

## 5. 人工恢复边界

| 操作 | 语义 | 进度与数据约束 |
|---|---|---|
| 重试 | 重新执行原事务 | 不改原事件；不确定提交先核对目标回执 |
| 共同校验点修复（已有） | 在共同历史点修复差异 | 完成后仍暂停；历史报告不改写为MATCH |
| 失败事务补偿（待做） | 恢复受影响身份的事务前状态，再允许重放 | 保留原事务、无主键ROW_ID、主键移动及重复变更顺序；补偿不提前算原事务成功 |
| 手工补数据（待做） | 审阅的类型化目标数据补丁 | 默认只写目标；前后状态/行数可审阅；漂移、依赖和权限不符拒绝 |
| 目标事务跳过（待做） | 对指定目标不应用一整个已知事务 | 生成SKIP凭据和一致性缺口，安全覆盖进度可前进，但不得伪装为已应用 |
| 采集范围隔离/排除（待做） | 针对采集/解码未完成处的独立缺口计划 | 影响全部相关订阅；必须证明范围边界、留存原日志；无法证明则拒绝并引导日志恢复/合格源/新基线 |

“类似MySQL从库操作”指操作体验和可恢复性，不是照搬数据库服务器命令。MySQL官方也区分GTID与非GTID的跳过方式，参见[事务跳过](https://dev.mysql.com/doc/refman/8.4/en/replication-administration-skip.html)。Rivomesh是异构同步服务，应使用自己的可审计回执和缺口协议，不向源库注入空事务、不直接修改源 `gtid_executed`，也不把 `sql_replica_skip_counter` 当作跨产品通用实现。

目标已提交而日志ACK落后时，应恢复确认，不能把已经生效的数据再标记为“未应用跳过”。一个目标跳过不应隐式影响其他目标。采集层排除则可能影响全部相关目标，审批范围必须明确。消息队列/分析库按各自可验证协议实现，不承诺它们具备SQL本地跨表事务。

缺口建议记录：源身份/坐标范围、事务和原始/规范化摘要、目标范围、原因、操作者/批准、原事件位置、SKIP/补偿回执、后续对账和处置状态。OPEN、修复中、已验证修复、已明确接受丢失应区分；“接受丢失”不能显示成“完全一致”。最终枚举和状态迁移为待实施设计。

## 6. 源端及Java兼容性验收口径

| 源 | 现状 | 未完成要求 |
|---|---|---|
| MySQL5.7 | 5.7.44基础链路证据 | 当前V3对象/恢复/HA及运行时档案补齐 |
| MySQL8.0 | 8.0.46历史V2/HA等证据 | 当前发布V3和新增恢复能力补验 |
| MySQL8.2 | 未发现专项完整证据 | 新增版本档案、实现差异和实测 |
| MySQL8.4 | 代表性V3/恢复已验收 | 扩展认证、日志特性、拓扑、目标和JDK矩阵 |
| PostgreSQL | SOURCE目录为PLANNED | 一致性快照/LSN/逻辑槽、事务和源切换；PG目标支持不算源支持 |
| Oracle | SOURCE目录为PLANNED | 路线、版本、权限及分发条件；SCN/redo/归档、事务、类型及恢复 |

PG使用复制槽导出快照与流位置衔接；槽恢复可能重发，因此需去重。主备续传能力与确切版本及槽同步条件有关，不能泛化到全部版本。[PG逻辑解码](https://www.postgresql.org/docs/18/logicaldecoding-explanation.html)、[PG故障切换](https://www.postgresql.org/docs/18/logical-replication-failover.html)。Oracle方案须区分源数据库及incarnation，不能只存一个数字SCN，见[Oracle19 LogMiner会话字段](https://docs.oracle.com/en/database/oracle/oracle-database/19/refrn/DBA_LOGMNR_SESSION.html)。以上为设计依据，不是新增连接器已经实现。

Java矩阵必须绑定候选包SHA、实际JVM/架构、驱动、源版本/模式、目标、日志、权限/TLS与负载。每个批准的源档案至少与五JDK执行全量、增量、重启和内容验证。若首批为四条MySQL版本档案+一个PG档案+一个Oracle档案，最低为30个“源档案×JDK”基线组合；这不是所有目标、类型、HA和安全用例的总数。更细矩阵按已批准档案扩展，未跑/失败/实验/不支持状态必须分别展示。

## 7. 建议实施顺序，不是工期承诺

| 阶段 | 工作 | 退出条件 |

| M2 | 节点注册、远端命令、权限/审计、控制HA和会话连续性 | 两节点同一入口控制、分区/旧owner/控制器故障测试通过 |

## 8. 待细化决策（不重复询问已确定范围）

- 集群控制后端首批支持产品、HA拓扑及Agent认证/注册方式；本地与共享档案如何升级。
- 会话空闲/绝对时限、浏览器关闭后记住登录、外部身份方式；这些是可配置策略，不影响先写接口和验收。
- PG首批确切版本、每任务database/schema范围及切主槽方案；Oracle首批版本、LogMiner/XStream路线、CDB/PDB/RAC/存储和驱动分发条件。
- 首批人工恢复的目标/日志档案、超大原事件保留位置和支持的受控源范围排除方式；未知边界始终不能假装已成功。
- Linux架构、真实K8s/CSI、厂商集群、硬件/网络/存储档案及压测资源；不编造统一TPS或恢复秒数。
